# specs.moukaeritai.work

`specs.moukaeritai.work` は、`moukaeritai.work` 配下のソフトウェアとサービスで共有・遵守する技術仕様および設計規約を集約するためのサイトです。

API仕様、データスキーマ、通信プロトコル、識別子、命名規則、互換性要件などに加え、利用者や他のソフトウェアから観測・操作されるインターフェースの一貫性を定めるサーフェス規約を公開します。仕様は、人間が参照できる文書として記述し、用途に応じて機械可読な定義も提供します。

## 目的

このサイトは、個々のソフトウェアやサービスで同じ設計判断を繰り返すことを避け、実装間の一貫性、予測可能性、相互運用性および保守性を高めることを目的とします。

ここで公開する仕様は、単なる実装例ではなく、複数のプロジェクトから参照できる共通の設計基準として管理します。

## 対象

主な対象は次のとおりです。

- APIの構造、表現形式、エラー表現およびバージョニング
- データスキーマ、識別子、列挙値および検証規則
- 通信プロトコル、メッセージ形式および状態遷移
- ファイル、ディレクトリ、URL、変数、コマンドなどの命名規則
- 後方互換性、変更区分、廃止および移行に関する規則
- Webアプリケーション、CUIアプリケーションその他のソフトウェアに共通するサーフェス規約

## 仕様文書

- [Development Work Classification and Change Governance for Coding Agents](specifications/software-development/coding-agent-development-work-classification.md) — 開発作業を複数の独立した分類軸で整理し、正本、仕様、実装、検証、外部サーフェスおよび変更意図を混同しないための英語規範。

## サーフェス規約

サーフェスとは、利用者または他のソフトウェアから観測・操作できる外部インターフェースを指します。サーフェス規約には、例えば次の事項を含みます。

### Webアプリケーション

- 標準的なURLおよびパス構造
- リソース名、アクション名、クエリパラメータ名の付け方
- ナビゲーション、状態、エラーおよび結果の表現
- 公開されるエンドポイントや文書の配置規則

### CUIアプリケーション

- 標準的なコマンド名およびサブコマンド名
- オプション、引数、環境変数の命名と優先順位
- 標準出力、標準エラー出力および終了コードの扱い
- ヘルプ、バージョン表示、確認操作および非対話実行の規則

サーフェス規約は、内部実装を一律に制約するものではありません。外部から見える構造と挙動を可能な範囲で統一し、利用者が別のソフトウェアでも既知の規則を再利用できる状態を目指します。

## 仕様の記述方針

各仕様では、可能な限り次の事項を明示します。

- 対象範囲
- 規範的要件と参考情報の区別
- 必須、推奨、任意などの要求水準
- 適合例と不適合例
- バージョンおよび変更履歴
- 互換性への影響と移行方法
- 関連する機械可読定義

仕様同士が競合する場合に備え、適用範囲、優先順位および例外条件も明確にします。

## バージョン管理と公開

このサイトのソースはGitでバージョン管理します。`specs.moukaeritai.work` ブランチを既定ブランチおよび公開内容の基準となるブランチとして使用します。

サイトはGitHub Actionsのワークフローでビルドし、GitHub Pagesにデプロイします。生成物を直接編集するのではなく、原則としてソースを変更し、ワークフローによって公開物を再生成します。

## 現在の状態

現在は初期構築段階です。仕様の分類、文書構造、ビルド方式および公開ワークフローは、リポジトリ内で順次定義します。
